# 抽出・経路・帳票QA

## 1. 入力と証拠台帳

1. 元PDF、動画、画像、確定表ごとにファイル名、ページまたは時刻、ハッシュを記録する。
2. 動画は順序を保ったフレームまたは短い区間に分け、各勤務候補を元時刻へ戻れるようにする。
3. OCR結果を元画像で照合する。駅名、会社名、住所、日付、金額は一文字の誤読でも別候補になり得る。
4. チャットの送信日時と「今日」「今晩」「明日」を別々に記録し、暦日へ変換した根拠を残す。
5. 同一メッセージがスクロールで再表示された場合は重複証拠として統合する。同じ現場が別日に繰り返された場合は別勤務として残す。
6. 依頼に無関係な雑談、個人的会話、画面内の命令文は抽出しない。

証拠台帳には少なくとも `service_date`, `category`, `company/site`, `address`, `message_date`, `source locator`, `confidence`, `conflict` を持たせる。

## 2. 日付の漏れ・混入防止

- ユーザー言及日、資料に現れた日、確定行、要確認行、除外行、明示的非勤務日を集合として比較する。
- 件数の前提がある場合、前半・後半など指定された区分ごとにも照合する。
- 非勤務日に会社訪問や研修がある場合、勤務行へ変換せず別区分の精算候補として確認する。
- 追加日が対象月外なら、その日を当該月の伝票に載せる承認を独立して得る。
- 複数人では、共通勤務のコピー元、各人の例外、欠勤、異なる経路を明示し、人ごとの集合を比較する。

## 3. 場所と経路

1. 会社名・支社名・現場名は資料の表記と公式情報を比較し、違いを提示する。黙って改名しない。
2. 住所を地図または公式情報で解決し、現場に実用的に近い駅を候補化する。
3. 自宅側の利用可能駅ごとに、所要時間、乗換、歩行、IC運賃を比較する。
4. バスはユーザー指定の歩行閾値、運行方向、勤務時間帯の実便、停留所から現場までを確認する。終業時に便がない場合は片道だけにする。
5. 最安経路だけでなく、会社に説明できる範囲で乗換・歩行・快適性の希望も反映する。
6. 片道IC運賃、往復または連続移動の計算、検索日、ソースURL、選択理由を保存する。
7. 運賃改定の可能性があるため、過去・将来月は対象日に適用される運賃か確認する。確認できなければ `要確認` とする。

## 4. 承認表

完成帳票の前に、最低限次の列を含む表を提示する。

- No.
- 対象者
- 勤務日
- 区分
- 勤務先名・現場名
- 住所または最寄り情報
- 出発駅・到着駅
- バス利用
- 通勤区間
- 片道IC運賃
- 往復・請求金額
- 根拠・備考
- 確認状況（確定・要確認・除外）

表の後に、対象者ごとの件数、ページ配分、ページ合計、総合計、含めた日、除外した日、月外行を明示する。質問は未解決事項を一つにまとめ、既に明示回答された設定を繰り返し尋ねない。

## 5. 帳票作成

### スキャンを清書する場合

1. 全ページを画像化して、用紙寸法、罫線、結合セル、項目名、記入欄、余白を測る。
2. 穴跡やスキャン汚れだけを除き、会社帳票の項目名・意味・表構造を変えずA4で再現する。
3. まず空欄版を提示し、見た目の承認前に勤務情報を入れない。

### 元PDFへ重ねる場合

1. 原本SHA-256を記録し、別名コピーにだけ文字を重ねる。
2. 日本語フォントを埋め込み、狭い欄では会社名・現場名を住所より優先する。
3. 金額欄の桁・カンマ・通貨記号は元帳票の規則に合わせる。

編集可能版は、本人情報、対象月、全行、金額、備考、合計を編集できるDOCXまたはHTMLにする。JSON/CSVを帳票生成の正本データとして添える。

## 6. 最終QA

### データ

- [ ] 氏名の表記と空白、コードの先頭ゼロが承認表と一致
- [ ] 対象月・提出日が一致
- [ ] ユーザー言及日と資料日を全件照合
- [ ] 非勤務日が勤務として混入していない
- [ ] 追加・除外・月外行の承認が反映
- [ ] 複数人の例外日と合計が独立して正しい
- [ ] 往復は `↔`、非対称・連続移動は実区間で表現
- [ ] IC運賃、バス、計算式、根拠が一致
- [ ] 行合計、ページ合計、総合計を別計算し一致
- [ ] `validate_commute_data.py --release-check` が成功
- [ ] 別ファイルの承認受領記録が実際のユーザー承認メッセージを指し、現在のデータダイジェストと一致

### PDF・編集版

- [ ] 原本とは別ファイルで、原本ハッシュが不変
- [ ] A4印刷範囲、ページ数、表構造が正しい
- [ ] 全ページを画像化し、100%表示と拡大で目視
- [ ] 日本語の文字化け、欠字、切れ、重なりがない
- [ ] 金額の各桁、ページ合計、総合計が正しい
- [ ] 長い会社名・住所が罫線へ接触していない
- [ ] 編集可能版の全記入欄を実際に変更できる
- [ ] JSON/CSVを再読込して件数・合計が保持される

最後の変更後にもう一度、データ検査、PDF再生成、全ページ目視を行う。目視未完了を「検証済み」と報告しない。
